# StudyFlow: постоянный сайт

Подготовлена конфигурация Render. Она сохраняет React, FastAPI и SQLite.
Одна ссылка открывает интерфейс, а запросы идут на тот же домен через `/api`.
Ноутбук после размещения можно выключать.

Это общее демо с кодом доступа. Все участники видят одну базу заданий и результатов.
Для личных кабинетов разных школьников потребуется отдельный этап разработки.
Онлайн-сервис начинает с новой базы; локальная база остаётся на твоём компьютере.

## 1. Файлы для GitHub

1. Скачай `StudyFlow_Public.zip` и распакуй его в новую папку.
2. Открой внутри папку `StudyFlow`. В ней должны быть `Dockerfile`, `render.yaml`,
   `backend` и `frontend`.
3. Этот архив содержит исходники для размещения. Секретов, локальной базы,
   установленных зависимостей и виртуального окружения в нём нет.

Если хочешь обновить рабочую папку на Windows, используй отдельный
`StudyFlow_Hosting_changes.zip`: распакуй внутрь существующей папки StudyFlow.

## 2. Загрузить проект на GitHub

1. Открой https://github.com и войди либо создай аккаунт.
2. Открой https://github.com/new.
3. Название репозитория — `studyflow`. Можно выбрать **Private**:
   исходный код останется закрытым, а опубликованный сайт будет доступен по ссылке.
4. Не добавляй README автоматически: он уже есть в архиве. Нажми **Create repository**.
5. На странице пустого репозитория нажми ссылку **uploading an existing file**.
   Если репозиторий уже содержит файлы: **Add file → Upload files**.
6. Перетащи содержимое распакованной папки StudyFlow. Перетаскивай её содержимое,
   чтобы `render.yaml` и `Dockerfile` были сразу в корне репозитория.
7. Нажми **Commit changes**. Проверь, что в корне видны `backend`, `frontend`,
   `Dockerfile`, `render.yaml` и `.dockerignore`.

Никогда не загружай свою `backend/.env`, API-ключ или `studyflow.db`.

## 3. Разместить на Render

1. Открой https://dashboard.render.com и войди / зарегистрируйся.
2. Нажми **New → Blueprint**.
3. Подключи GitHub и разреши Render доступ к репозиторию `studyflow`.
4. Выбери этот репозиторий. Путь Blueprint — `render.yaml`.
5. Render покажет один Docker-сервер и постоянный диск на 1 ГБ.
   План в файле — `0.5c-512mb` (0.5 CPU, 512 МБ), регион Frankfurt.
6. В поле **OPENAI_API_KEY** вставь свой действующий API-ключ прямо в Render.
   Его не нужно вставлять в исходный код или присылать в чат.
7. Проверь итоговую стоимость. Этот вариант использует **платный сервер и диск**.
   Бесплатный сервер Render не сохраняет SQLite между перезапусками.
   Актуальные цены: https://render.com/pricing.
8. Если стоимость подходит, нажми **Deploy Blueprint**. Render сам соберёт
   интерфейс и сервер; устанавливать Docker на ноутбук не требуется.
9. Дождись успешного размещения / состояния **Live**. Публичная ссылка появится
   на странице созданного сервиса. До этого сайт ещё не опубликован.

Код доступа **STUDYFLOW_DEMO_ACCESS_CODE** Render создаст автоматически как
случайный секрет. Открой сервис → **Environment**, посмотри его значение и
используй на экране входа. Участникам демо можно передать ссылку и этот код.
OpenAI API-ключ остаётся только на сервере.

## 4. Проверить публичную ссылку

1. Открой ссылку на телефоне через мобильный интернет.
2. Введи код доступа → открой StudyFlow.
3. Пройди: фото → распознавание → подтверждение → план → Tutor → тест → карта.
4. Обнови страницу: задание и результат должны сохраниться.
5. Через Render перезапусти сервис и проверь сохранение ещё раз.

Пример фото доступен в архиве `demo/assignment.png` и на опубликованном сайте
по пути `/demo/assignment.png`.

## Если появляется ошибка

- Сборка Docker: пришли последние строки **Logs**, без секретов.
- «Код доступа неверный»: проверь значение STUDYFLOW_DEMO_ACCESS_CODE в Environment.
- AI не отвечает: проверь OPENAI_API_KEY, доступность модели и состояние API-аккаунта.
- Исчезает база: постоянный диск должен быть смонтирован в `/var/data`, а
  STUDYFLOW_DATABASE_URL равен `sqlite:////var/data/studyflow.db`.
- Health check должен использовать `/api/health`. API на размещённом сайте
  находится под `/api`, а локальный API по-прежнему работает без этого префикса.

## Проверка подготовленных файлов

Backend и frontend проверены отдельно; тест размещённого API выполняет полный
цикл с настоящими SQLite, Planner, Mini Test и Knowledge Map, подменяя внешний AI.
Новая браузерная проверка: `qa/run_hosted_e2e.py` в полной сборке проекта.
Фактические результаты и ограничения — в `PROJECT_STATE.md`.

Полный Docker-образ и размещение в твоём Render-аккаунте здесь ещё не выполнены.
После Live необходим один прогон с настоящим OpenAI по публичной ссылке.
