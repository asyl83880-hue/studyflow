# Размещение версии с аккаунтами

## Существующий сервис

Render: https://dashboard.render.com/web/srv-db3uichsrm7s73a9aseg
Сайт: https://studyflow-27y8.onrender.com
Docker, Free, Frankfurt; health check `/api/health`; один сервер с React и FastAPI.

## Подготовка Neon

Используй принадлежащий владельцу бесплатный проект в регионе AWS Frankfurt,
если он доступен в аккаунте. Не включай платный тариф без отдельного согласования.

1. Создай PostgreSQL-проект и рабочую ветку.
2. Включи Managed Neon Auth на той же ветке; IP Allow/Private Networking не менять ради этого.
3. Разреши доверенный origin `https://studyflow-27y8.onrender.com`.
4. Для разработки разреши нужный localhost/127.0.0.1 origin.
5. Для почтового подтверждения и восстановления включи Email OTP.
6. Получи pooled PostgreSQL URL и реальные Auth Base / JWKS URL из конфигурации Neon.

Не угадывай адрес Auth или JWKS по названию проекта. Они относятся к конкретной ветке.
Не используй временную незаявленную базу вместо базы пользовательского аккаунта.
Тариф и лимиты Neon нужно проверить при создании; данные должны переживать остановку compute.
Для промышленной доставки писем Neon рекомендует собственный SMTP; до готовности
такой доставки подтверждение и восстановление по почте нельзя считать проверенными.

## Секреты и переменные Render

Добавляй значения с сохранением остальных существующих переменных:

| Переменная | Значение |
| --- | --- |
| STUDYFLOW_POSTGRES_URL | Секретный pooled URL базы Neon, с TLS. |
| STUDYFLOW_REQUIRE_POSTGRES | `true` для публичного сервиса. |
| NEON_AUTH_BASE_URL | Реальный публичный URL Managed Auth на этой ветке. |
| NEON_AUTH_JWKS_URL | Реальный JWKS URL той же ветки. |
| OPENAI_API_KEY | Существующий рабочий серверный ключ. |
| OPENAI_MODEL | `gpt-4o-mini`, если не переопределено. |
| STUDYFLOW_AI_USER_DAILY_LIMIT | `20` по умолчанию. |
| STUDYFLOW_AI_GLOBAL_DAILY_LIMIT | `100` по умолчанию. |

STUDYFLOW_POSTGRES_URL имеет приоритет над прежним SQLite URL. Старое приложение
игнорирует новую переменную, поэтому инфраструктуру можно подготовить до переключения кода.
Значения секретов не выводить в логи, ответы или исходники.

## Безопасный порядок выпуска

1. Завершить CI ветки с аккаунтами, включая PostgreSQL и Docker.
2. Подготовить Neon, Auth, доверенные домены и значения в Render.
3. Убедиться, что Auth и PostgreSQL относятся к одной выбранной ветке.
4. Слить код в main; Auto Deploy обновит существующий сервис.
5. Дождаться Live конкретного deployment, затем проверить фактический сайт.

Не выкатывай новую версию с пустыми Auth URL: hosted-сервер откажется стартовать.
Режим STUDYFLOW_REQUIRE_POSTGRES=true также запрещает случайный запуск публичных
аккаунтов на временном SQLite. /api/config показывает только публичный URL входа
и флаги настройки AI/постоянного хранилища — без ключей и строки подключения.

## Проверка после Live

- Главная открывается; /api/health отвечает status: ok.
- /api/config: persistent_storage=true, auth_url заполнен, ai_ready соответствует настройке.
- Неавторизованный /api/tasks отвечает 401.
- Регистрация → выход → вход → reload восстанавливают правильный аккаунт.
- Второй аккаунт не видит задания, тесты, результаты и карту первого, включая прямые ID.
- Фото → черновик → подтверждение → план → Tutor → тест → результат → карта работают с настоящим AI.
- После нового развёртывания задания и результаты сохраняются в Neon.
- Подтверждение почты и восстановление пароля действительно доставляют и принимают код.

## Совместимость данных

Личные записи используют новые таблицы assignments, practice_tests,
practice_results, practice_answers, task_request_keys и usage_counters.
Прежние общие таблицы демо не удаляются и не назначаются первому зарегистрированному
пользователю. Пароли и сессии управляются Neon Auth в его отдельной схеме.
